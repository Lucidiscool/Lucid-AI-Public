# LucidAI local chat

## Automatic assistance and concise replies

Replies now lead with the answer and default to 1–3 sentences or up to three useful bullets. Ask for detail when needed. Web reports lead with a short summary rather than background and feature lists.

Automatic memory and web are on by default. A local model decision checks each ordinary message. It can save explicitly stated lasting personal facts/preferences and choose a public search query when current information helps. Every saved memory and web query is shown in the terminal. Decisions can be missed or mistaken; `/memories` and `/forget ID` let you review and remove memories. Secret/sensitive messages are excluded from automatic actions using conservative filters. Automatic memory is limited to supported first-person statements; it does not mine old transcripts or web pages. New name facts replace previous automatically saved names; other facts accumulate for user review.

`/auto-memory off` and `/auto-web off` disable each feature persistently; use `on` to re-enable. `/remember` remains available, and `/search` always forces a search even when automatic web is off. Only generated public search queries are sent to search providers; the planner receives the current message locally, not saved memories. Exact forgotten facts are blocked from automatic re-saving using local hashes; an explicit `/remember` can still save them again. Old transcripts remain unchanged.

## Web search and research

In `lucid`, use `/search YOUR QUESTION` for one search and up to three readable pages. Use `/research YOUR QUESTION` for up to three search queries and eight readable pages, with local evidence extraction and a report comparing sources. This is bounded research, not an exhaustive investigation. Ordinary chat can choose quick search when automatic web is enabled.

The terminal shows queries, URLs, reading failures, evidence extraction and report-writing progress. Reports include numbered source links. JSON activity logs and Markdown reports are saved under `personal/research/`; Ctrl+C cancels the operation and closes chat, retaining the activity log. Search queries go to external search providers and visited sites see page requests. Memories and full conversations are not sent to search providers. No API key is required; public search providers can rate-limit or block requests.

Only public HTML/text pages are supported; PDFs, sign-ins and JavaScript-only pages may be skipped. URL checks block private/local addresses and nonstandard ports, including redirects. Page content is untrusted evidence, cannot execute code or invoke tools, and is bounded in size. Source summaries and citations are generated by the local model and can be mistaken: inspect the linked pages for important claims. Retrieval date is recorded separately from publication date.

Web dependencies are in `requirements-web.txt`. Search uses [DDGS](https://pypi.org/project/ddgs/9.13.0/).

## Feedback

After an answer, use `/good` or `/bad`, optionally followed by a reason. Use `/correct PREFERRED ANSWER` to supply the answer you wanted. `/feedback` shows counts and recent feedback; `/unrate` removes the latest answer's rating. Re-rating an answer replaces its earlier rating. Resume a conversation to rate its last answer later.

Feedback is saved locally in `personal/feedback.json` with the last three conversation turns and the model name. Up to two relevant examples are selected by question word overlap and supplied to future replies, including new chats. This can help it adapt, but does not guarantee improvement or change model weights. Negative answers are never included as positive examples. Feedback remains separate from `/forget` memory; use `/unrate` to remove it. Keep one chat terminal open when changing feedback.

This version collects material for future reviewed fine-tuning; it does not automatically train or replace the model. Bare ratings provide less useful guidance than explanations and corrected answers.

Double-click `chat-local.cmd`. The historical `chat-directml.cmd` launcher now opens this chat too. The model runs locally using llama.cpp Vulkan on the RX 6600; no training is required to start chatting.

- Backbone: Qwen3-4B-Instruct-2507, Apache 2.0, https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507
- Quantization: Unsloth Q4_K_M, https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF
- Runtime: official llama.cpp b11026 Windows Vulkan build.
- Model and runtime SHA-256 checks were verified by `setup_open_model.py`. Installed paths, pinned revision and model checksum are in `local_model.json`.
- Context: 8192 tokens including replies. Oldest conversation pairs are removed when necessary. Oversized individual messages are rejected.

Run `lucid` to start a new conversation, or `lucid --resume` to reopen the latest saved chat. Completed turns save automatically under `personal/`. Use `/chats` to list saved IDs, `/load ID` to reopen one, `/new` to start fresh, and `/quit` to exit. `/save` saves the current conversation explicitly. Older exports under `runs/` remain unchanged.

Use `/remember My name is Elliott` to save an explicit fact across chats. `/memories` lists saved facts and IDs; `/forget ID` removes one and `/forget all` clears saved memories. Removal does not erase the original text in old conversations: use `/new` to stop using the current conversation as context. Memory is stored locally in `personal/memories.json`, limited to 20 facts of 500 characters each (300 for automatic facts). Keep one chat terminal open at a time when editing memory.

Conversations are not used for automatic training. Web access is automatic when enabled or forced through `/search` and `/research`. The model can make mistakes. Full transcripts stay on disk even when the oldest turns no longer fit the model's context window.

The server remains loaded after chat closes so reopening is quick. Its log is `runs/local-server.log`; it listens only on `127.0.0.1:8097`. To release GPU memory, close `llama-server.exe` through Task Manager. Only one generation runs at a time.

`chat-scratch.cmd` opens the original from-scratch model. All earlier checkpoints remain intact. `lucid.py chat --checkpoint PATH` also preserves the old checkpoint interface.

`evaluate_local.py` runs the existing reserved dialogue and general review prompts at temperature zero and saves actual responses in `runs/open-model-review.json`. This is a small qualitative check, not a general intelligence benchmark. Do not train on those held-out prompts.
